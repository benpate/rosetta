# rosetta — Notes for AI Agents

Rosetta is a collection of data-manipulation packages (conversion, comparison, schema validation, typed maps/slices, template helpers) shared across the benpate/EmissarySocial ecosystem. See [README.md](README.md) for the package roster. The `null` package has its own notes in [null/AGENTS.md](null/AGENTS.md).

A recurring defect pattern in this repo: two implementations of one contract drifting apart (sibling groupers, sibling map types, two slice-growth routines). When you change one implementation of a shared contract, diff its siblings and keep them in agreement. And when adding fuzz targets, prefer differential tests against a stdlib oracle over "assert no panic", and bound any input that drives allocation.

## schema

- **`Schema.Set` validates before writing, and callers must expect errors.** It can return `derp.Validation` errors (unknown path, required-empty, pattern/enum violations), clamp integers to `Minimum`/`Maximum`, truncate strings to `MaxLength` on rune boundaries, and rewrite values through format functions. It is not a plain type-coercing setter; a Set that "obviously should work" can still fail or store a different value than was passed.
- **`Schema.Validate` returns `(bool, error)`.** The bool means "the value was coerced or rewritten during validation", not success. Element-level `Validate` methods are still error-only.
- **`Validate` reports an ERROR whenever a format rewrote the value — so a sanitizing field is "invalid" exactly when it worked.** The rule is explicit in [schema/validate.go](schema/validate.go): a value that had to be clamped or reformatted is not valid as-given, and `Validate` returns `derp.Validation` *even though it also writes the corrected value through*. Every sanitizing format (`css`, `css-declarations`, `html`, `text`, any clamping numeric) behaves this way. Two consequences, both of which have bitten: `Validate` needs a **pointer** to write the rewrite through, and passed by value it errors with nothing changed, which reads like rejection and is not. And **tests must assert against `Set` or `form.SetURLValues`, never `Validate`** — `Set` rewrites in place and is what a save path actually calls, so a sanitizing field saves correctly while `Validate` calls it invalid. `require.NoError(Validate(...))` on such a field is a guaranteed false failure.
- **The per-type `Validate(any)` methods (Any, Boolean, Integer, Number, String) are intentional, not dead code.** They are outside the `Element` interface and have no in-repo callers, but they are deliberately retained. Do not delete them; keep their behavior and error messages consistent with the live `validate_*` free functions when changing validation.
- **Array-typed properties must implement `ArrayGetterSetter` via their POINTER.** `validate_Array` requires `GetIndex`/`SetIndex`/`Length`. Add a compile-time `var _ schema.ArrayGetterSetter = (*T)(nil)` assertion for every new slice type used in a schema. `addressableItem` in [schema/validate_array.go](schema/validate_array.go) exists so composite array items are validated against an addressable pointer copy (pointer-receiver accessors would otherwise be unreachable on by-value items); do not "simplify" it away.
- **Map-ness is declared, never inferred.** A map type opts in via the `MapTyper` interface (`IsMap() bool`); only then does `validate_Object` skip absent keys as "absent optional = empty". A struct missing a `GetStringOK`/`GetPointer` accessor still errors loudly, on purpose — that error is the signal that an accessor is missing.
- **All in-package inheritance goes through `inheritElement`, which allocates the child's `Properties` map before delegating.** `Object.Inherit` has a value receiver (the `Element` interface is satisfied by value types, so a pointer receiver would be a breaking change), which means a nil-map allocation inside `Object.Inherit` cannot stick. Calling `element.Inherit(parent)` directly on an Object with a nil `Properties` map silently does nothing.
- **The scalar `Inherit` no-ops report 0.0% coverage forever.** They have empty bodies, and `go tool cover -func` prints 0.0% for zero-statement functions. They are tested with `require.NotPanics`; don't chase them.
- **Errors name a value's type and path, never the value.** Every object-level detail and every value arriving through `Set`, `SetAll`, `SetURLValues`, or `SetProperty` goes through `typeName` in [schema/utils.go](schema/utils.go). Callers validate and set models that hold passwords, keys, and tokens, and Emissary stores every reported error verbatim: a failed `Validate` of an OAuth client used to write its secret into the error log (EmissarySocial BUG-173). Field-level format, pattern, and enum errors, and the before/after values in `rewrites.details()`, still echo the one field that failed. Do not give a secret-bearing field a format or pattern without accounting for that. `TestErrorDetails_NameTypesNotValues` pins the rule.
- **`validate_Object` ranges over a map, so multi-property validation failures are non-deterministic in order.** Run schema-heavy tests with `-count=3` when hunting flaky validation behavior.
- **Schema walks every nested path itself; a map only stores one key at a time (BUG-234).** `setProperty_Object` writes a map's keys through `KeySetter.SetKey` and decides each child in [schema/schema_set_child.go](schema/schema_set_child.go). Schema imports mapof and sliceof so it can create their containers, so neither may ever import schema; that is why `ObjectSetter` and the three `SetObject` methods are gone. At each segment, an existing child is entered when its kind matches the element, and is otherwise a `derp.Validation` error, never replaced (a scalar included). A missing child is created from the element: Object makes a `mapof.Any`, Array a `*sliceof.Any`, and Any chooses a list when the next segment is plain digits and a map otherwise. A typed parent such as `mapof.Object[T]` supplies its own child type. A plain `map[string]any`, `[]any`, or `[]mapof.Any` is written through the rosetta type with the same layout and stored back as its original type, because callers compare stored types.
- **Beneath an Any element, a list index must be plain digits and no greater than the list's length.** `checkAnyIndex` enforces it because request keys reach `Set` unfiltered (Emissary's `edit-registration` and `add` steps), and an unbounded index allocates a list of any size (BUG-116). An Any has no `MaxLength` to carry a limit, which is the only reason this check exists.
- **An Array element is bounded only by its own `MaxLength`, by design (decided 2026-10-05).** Limits on list length belong in the schema, never in the data accessors: do not add an index bound to `setOtherChild`, `SetIndex`, `GetPointer`, or `growSlice`. With a `MaxLength`, `Array.GetElement` refuses a later index and `Set` reports it as an unknown field. Without one, a single path such as `tags.5000000` builds a list of 5,000,001 items. So every Array that request keys, form posts, or socialRules can write into must set `maxLength`.
- **New lists are stored as `*sliceof.Any`, matching translate's `value: []` and `append` rules.** Writes into a list held by pointer need no copy, so they stay visible to every reader of the parent.
- **`Get` reads through [schema/schema_get_readable.go](schema/schema_get_readable.go), and never changes what it reads (BUG-234 follow-ups, tests in [schema/followup_test.go](schema/followup_test.go)).** A list or map held by value, or a plain `[]any` or `map[string]any`, is read through a pointer to a copy. A struct held by value is not, on purpose: Emissary's `newStartupStream` relies on `SetAll` refusing a whole `model.Content`, and `TestFollowupGuard_StructHeldByValue` pins that. A read past the end of a list (an index at or beyond its length, or `next`) returns the zero value of the element at the end of the path, and no getter is called: sliceof's `GetPointer` grows the list to reach an index, so calling it would allocate the whole length, even on a copy (one read of index 10,000,000 allocated 827 MB). `TestFollowup_GetPastTheEndReturnsZero` measures the bytes. A scalar list item is returned as its value, but a struct's fields are still returned by pointer, and translate's `path` rules store those pointers; `TestPathRunner_StructSourceGuard` pins the JSON they produce. `Set` refuses a path with an empty segment (`"name."`) as an unknown field.

## translate

- **`forEach` gives its item rules the schema `{key: String, value: <item element>}`.** The item element is an Array's `Items`, an Object's `Wildcard` (or Any for an Object with named properties), or Any beneath an Any. Before 2026-10-05 the item rules read through the item element itself, so `key` and `value` were readable only beneath Any, and a map declared as an Object was refused as a source. `TestForEach_TypedSources` pins both.
- **Beneath a typed Array, write list items by index, not with `value: []` and `append`.** `value` stores a `sliceof.Any` by value, which fails the Array's validation (only its pointer is an `ArrayGetterSetter`), and `append` cannot read a list that is not there yet. `{target:"artists.0.id", …}` works: the container rule creates the list and its first item, and the Array's `maxLength` bounds the index. Both idioms still work beneath Any.
- **`value` and `append` write a deep copy of their constant, never the constant itself.** A Pipeline is parsed once and run for every caller, often concurrently: Emissary caches a Template's `socialRules` and every step's rules. Until 2026-10-06 the rules stored their own map or list in each output, so a later rule's write (`url.href` after `{target:"url", value:{}}`) went into the rule, and every document built from it shared one object and rewrote the others. `copyValue` in `utils.go` does the copy; `TestValue_NeverSharesItsValue` and `TestAppend_NeverSharesItsValue` pin it. Any new rule that writes a constant must copy it the same way.
- **A rule whose target is `""` replaces the whole output object.** Put it first, or it discards what earlier rules wrote. It is also the one way to start from an object whose `""` and `0` values survive: `mapof.Any`'s typed setters delete zero values, so writing those fields one at a time beneath a typed property drops them (beneath Any they survive).

## schema/format

- **Format functions rewrite values, and Set stores what they return.** A format is `func(string) (string, error)`; the returned string is what lands in the object, not the input.
- **Every string format must be idempotent, because `validate_String` applies it twice.** It formats, truncates to `MaxLength`, then formats again so the stored value is stable. A format that rewrites its input must therefore accept its own output; `FuzzFormats_Idempotent` in [schema/format/allFormats_fuzz_test.go](schema/format/allFormats_fuzz_test.go) enforces this for every generator with no exemptions. The `webfinger` format used to require a leading `@` and then strip it, so a handle failed validation on the second pass and no record holding one could be saved; it now returns the handle unchanged and rejects display-name and angle-bracket forms. A format that legitimately rewrites (HTML, CSS, `CSSDeclarations`, Markdown, URL, URI, Email) must also be listed in `transforms` in `FuzzFormats_AcceptedValueIsDerivedFromInput`, or the fuzzer reports its rewrite as an unrelated value.
- **The `url` format is strict.** Absolute URLs only, scheme limited to http/https/mailto, max 2048 bytes. Unknown format names fail `Schema.ValidateFormats()`. Data written before this enforcement may fail validation on its next Set.
- **Validation regexps live at package scope.** Compiling a regexp inside the returned closure runs on every validation (a measured 233x slowdown). Keep patterns hoisted, like `hostnamePattern` in [schema/format/network.go](schema/format/network.go).
- **`Text`, `NoHTML`, and `Summary` inherit `html.RemoveTags`'s angle-bracket data loss.** See the html section; the known-bug pins live in [schema/format/Text_test.go](schema/format/Text_test.go).

## convert

- **`convert.String` formats floats with a fixed 2 decimal places — it is lossy.** `100` becomes `"100.00"`, `3.14159` becomes `"3.14"`. Never round-trip numeric data through `convert.String`; format explicitly when precision matters. `loose.String` deliberately avoids this path to preserve exact source text.
- **The `*Ok` functions' second return means "the conversion was lossless", not "the value was naturally this type."** The non-Ok wrappers discard it.
- **`convert.Int` clamps to platform int width and clamps out-of-range floats.** Use `Int64` for wire data; a plain `Int` caps at 2^31 on 32-bit targets (including `GOARCH=wasm`).
- **There is no reflection fallback.** A named type (`type Foo string`, or any struct) that matches no concrete case or interface converts to `""`. This is why `mapof.Matchable[T].MapOfString()` loses every value for struct-typed `T` — pinned as a KNOWN LIMITATION in [mapof/matchable_test.go](mapof/matchable_test.go), not a bug to fix in mapof.

## list

- **Delimiters are effectively ASCII-only (open bug, BUG-115).** `PushHead`/`PushTail` join with `string(delimiter)` where delimiter is a byte, so Go rune-converts it: byte 200 is written as the two UTF-8 bytes `c3 88`, and `Index()` can never find it again. The constructors' `strings.Join(..., string(Delimiter))` calls share the flaw. Latent only because all five shipped list types (comma, dot, semicolon, slash, space) are ASCII. `FuzzList_Push` skips delimiters above 0x7f with a comment pointing here — delete that skip when the fix (`string([]byte{delimiter})`) lands.
- **`SplitTail`'s single-item behavior is important.** `"photo"` splits to `("photo", "")` — the whole value stays in the head, NOT the `RemoveLast`/`Last` decomposition `("", "photo")`. Real callers split `filename.ext` and depend on exactly this; its doc comment says so. Do not "fix" it.
- **`Last2`/`Last3`/`Last4` pad in the middle for lists shorter than N.** `Last3(["a","b"])` returns `("b", "", "a")` — they inherit `SplitTail`'s filename semantics, which makes them wrong for short lists. Zero known callers; the oddity is recorded in `TestLast_ShortListIsUnspecified`. Don't build on their short-list behavior.

## sliceof

- **A schema path segment can grow any sliceof slice without bound, by design (BUG-116).** `SetIndex`/`GetPointer` parse an index out of the path with no maximum, then `growSlice` appends until it is addressable, so `schema.Set(&obj, "tags.50000", "boom")` allocates 50,001 elements. The limit is the schema's job, not this package's (see the schema section): the Array's `maxLength`, or `checkAnyIndex` beneath an Any. Do not add a bound here. The fuzz suite caps indexes at `growthLimit = 1000` for the same reason, and keeps that cap.
- **Grouper `IsFooter` guards must be `index < 0`, matching `slice.Grouper`.** An `index <= 0` guard means the first group never closes. The four sliceof groupers and `slice.Grouper` implement one contract; keep them identical.
- **`FirstN` clamps negative n to 0.** The slice expression `x[:n]` panics otherwise; every sliceof type carries the clamp plus a regression test.

## mapof

- **Mutating methods take pointer receivers and call `makeNotNil()` first.** A value-receiver setter panics on a nil map (the zero value of every mapof type). `Slices.Add` follows the pattern; any new method that writes must too.
- **`Matchable[T].MapOfAny()` must copy entries directly — never hand `m` to `convert.MapOfAny`.** `Matchable[T]` is a `map[string]T`, which matches none of `MapOfAnyOk`'s concrete map cases (Go type switches match exact types, not underlying types) and falls through to its `MapOfAnyGetter` case, which calls straight back into the method: unbounded mutual recursion, fatal stack overflow, for every `T`. The in-code comment marks this; do not "simplify" it back.
- **`mapof.Template`'s getters take the data to render against, so they deliberately do not match `mapof.Any`'s.** Every getter is `GetXxx(key, data)` and reads through `evaluateAny`: a string or `loose.Template` is rendered against the data, and every other value is returned as it is, for `convert` to coerce. Nil data returns the source unchanged, and a failed render is swallowed as `""`; `Evaluate` is the one read that reports render errors. The bool, number, and time getters trim whitespace from the rendered text first, because `convert` rejects `" 6"`; `GetString` keeps it. Only top-level strings are templates: strings inside a list or map are returned unrendered. Its setters and whole-map methods (`MapOfAny`, `Equal`, `IsZeroValue`, `GetPointer`) still match `Any` and read source values. A string that compiles as a template is stored as a `loose.Template`, and every other string as itself, so a raw index read can return either: read it only through its methods. `Clone` deep-copies every map and slice but shares each `loose.Template`, which never changes once compiled.
- **`mapof.Template` never writes to its map when it renders; a template it compiles from a plain string comes from `loose.CachedTemplate` instead.** Option maps are shared by every request, and any write concurrent with any read of a Go map is a fatal, unrecoverable error, so compiling "back into the map" would crash under load no matter where the lock went. Only Go map literals and raw index assignments reach it, because parsing, JSON, and every setter compile templates into the map before it is shared.
- **`mapof.String.GetStringOK` returns `("", false)` for absent keys, on purpose.** Absent-key tolerance during schema validation is handled by `MapTyper`, not by loosening the getter contract. All mapof types implement `IsMap() bool` returning true, with compile-time assertions.

## funcmap

- **The trust-cast helpers each have a distinct trust contract; know it before piping data in.** `html` is a raw `template.HTML` cast — safety is per-call-site, so sanitize remote/federated content with `htmlMinimal` (bluemonday) first. `css` is a raw `template.CSS` cast reserved for owner/admin-authored stylesheets — never remote or query-string data. `attr` and `cssValue` are safe-by-construction: they reject any value containing context-breakout characters (returning empty) via `safeAttr`/`safeCSSValue`. `text` self-sanitizes through `html.FromText`; do not "harden" it further. `safeURL` guards navigation targets. When auditing templates, grep for `{{html`, `{{attr`, `{{css` and verify the piped value's trust.
- **`html/template` resolves function names at parse time.** A template calling a helper that a dependent's rosetta version lacks fails to PARSE, not just render. Adding a funcmap helper does nothing for downstream templates until they build against a rosetta that has it.

## html

- **`RemoveTags` mangles unescaped angle brackets in plain text (open bug, pinned in tests).** A bare `>` resets the write cursor and drops everything before it (`"6 > 5"` → `" 5"`); a doubled `<` duplicates preceding text (`"a<<br>b"` → `"aab"`), so output can exceed input length. It is NOT a sanitizer hole — no `<`/`>` survives, which `FuzzRemoveTags` proves. Reachable from user content via `schema/format.Text`/`NoHTML`/`Summary` and funcmap. The pins carry KNOWN BUG markers so a fix surfaces as a test failure; any fix must not let `<` through.
- **The fuzz file is [html/html_fuzz_test.go](html/html_fuzz_test.go), not `fuzz_test.go`.** A `fuzz*_test.go` glob misses it and you will write a duplicate.
- **When fuzzing sanitizer output, scope substring checks to tag spans only.** bluemonday escapes `<` in text to `&lt;`, so bare prose containing "onerror" is harmless; a naive `strings.Contains` assertion fails instantly on safe output.

## loose

- **This package is the receiving half of Postel's law: types that accept whatever a remote system or a hand-written file actually sends.** Its strict counterpart is `null`, which never coerces across JSON types; the split is deliberate — don't widen `null` or tighten `loose` to merge them.
- **`String` decodes with `json.Decoder.UseNumber()` to keep a number's exact source text** (`1.0` stays `"1.0"`). Never route it through `convert.String`, which would force two decimals.
- **`Int64` is `Int64`, not `Int`, on purpose, and its exact-integer fast path is important.** `convert.Int` clamps to platform int width (2^31 on 32-bit/wasm targets), and `json.Unmarshal` into `any` yields `float64`, silently rounding above 2^53 — the fast path preserves large integers. Precision beyond int64 is explicitly NOT a goal: larger values clamp, and integers nested inside arrays still round through `float64`.
- **A new tolerant type goes into `jsonTargets` in [loose/fuzz_test.go](loose/fuzz_test.go)** to inherit the universal properties (no panic, valid re-encode, fixed-point round trip). Gate cross-arch with `GOOS=linux GOARCH=386 go vet ./...` (plus `arm`, `js/wasm`).
- **`CachedTemplate` is the only package-level mutable state in `loose`, and it is deliberate.** It is a `sync.Map` of compiled Templates keyed by source, in [loose/templateCache.go](loose/templateCache.go): it stores only strings that compile, never changes an entry once stored, and stops growing at `templateCacheLimit`. `NewTemplate` stays uncached on purpose, because `UnmarshalJSON` feeds it arbitrary decoded text that would fill the cache. Call `CachedTemplate` only with template strings written by authors, such as Go literals and configuration.
- **`Template` never rejects a malformed template: it keeps the string as plain text, with no compiled template.** A typo in a template therefore renders literally instead of failing, so a caller that needs every template to compile must check `IsTemplate()` itself. `UnmarshalJSON` decodes through `String`, so it accepts the same scalars and rejects objects and arrays. Its fuzz target compares encodings, not values, because each decode compiles a new template. Its own `FuzzTemplate_*` targets check the compile decision against `text/template` directly, and skip executing templates that use `range`, `define`, `block`, `break`, or `continue`: those can loop without end, and templates come from trusted authors, so their running time is out of scope.

## delta

- **`Slice.SetValue` must copy the incoming and previous slices; keep the append-onto-fresh-slice pattern.** The Deleted list is compacted in place, which would write through to the caller's slice if aliased, and `slices.Clone(nil)` returns nil while `NewSlice`/`Reset` guarantee non-nil lists — the `append(make([]T, 0, ...), ...)` form satisfies both constraints at once.
- **`NewSlice` stores its variadic slice directly, so a later `SetIndex` can write through to caller memory.** Known residual aliasing; be aware of it when a caller retains the slice it passed in.
- **`Slice.SetIndex` grows without bound, like sliceof, and by the same design (BUG-116).** It rejects negative indexes then grows to any requested length, and it implements `schema.ArraySetter`, so the same schema-path route reaches it. The schema's `maxLength` is the limit; do not add one here. It cannot share `sliceof.growSlice` (different growth bookkeeping — appended slots are recorded as Added).

## channel

- **The package has open, structural defects — do not build new code on it without accepting them.** `Closed()` receives from the channel in its select, so it reports "closed" whenever a value is merely waiting and DISCARDS that value (its doc comment claims otherwise); Go offers no non-destructive closed test, so this cannot be fixed in general. Every producer (`Map`, `Pipe`, `Filter`, ...) sends without a cancellation select, so abandoned pipelines leak goroutines; even `PipeWithCancel` leaks, because its `output <- item` send is unguarded and cancellation never reaches upstream stages.

## Tooling

- **[revive.toml](revive.toml) sets `enableAllRules = true` with targeted overrides.** The high-signal revive categories in this repo are `suspicious assignment`, `identical branches`, `differs only by capitalization`, and `redefinition of the built-in`; most style findings on validators and test constants are accepted noise.
- **Check nilaway against the CI form before calling it red or green.** CI runs `nilaway -exclude-test-files=true` (see `.github/workflows/`); a plain local `nilaway ./...` adds findings from tests that deliberately call map setters on nil maps.
